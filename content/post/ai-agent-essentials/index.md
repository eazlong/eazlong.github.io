2023年，所有人都在比谁的LLM参数更大、跑分更高。到了2025年，风向变了——大家开始比谁的Agent能真正干活。

同一个LLM，装在聊天框里只能写诗作文，装进Agent却能自动写代码、跑交易、管供应链。差距不在发动机，在整车设计。

**LLM只是发动机，Agent才是那辆车。** 这句话被说烂了，但很少有人真的拆开看：车到底是怎么造的。

## 一、发动机的内在局限

LLM有三个结构性缺陷，注定了它不能单独干活：

### 1. 无状态（Stateless）

每次请求都是全新的。你不把上下文塞进prompt，它什么都不记得。这就像一台发动机，每次启动都要重新点火，没有仪表盘、没有里程表、没有历史记录。

### 2. 幻觉（Hallucination）

它生成的是"看起来合理"的文本，不是"事实正确"的答案。没有外部校验，发动机再强也可能把车开进沟里。

### 3. 无行动能力

LLM的输出只有token。它不能点击、不能查询、不能执行。再强的推理，如果碰不到真实世界，也只是纸上谈兵。

这些问题不是靠增大参数量能解决的。发动机的问题是，它只能产生动力，不能控制方向。

## 二、Agent的本质：从动力到控制系统的工程跃迁

Agent不是给LLM穿个外壳，而是给它装上一整套控制系统。这套系统解决的是三个根本问题：

### 记忆系统 = 车机系统 + 黑匣子

LLM的记忆不只是"记住上次说了什么"。工程上它分两层：

- **短期记忆（上下文窗口）**：当前任务的对话历史和中间状态。相当于车机系统的导航记录。
- **长期记忆（向量数据库）**：持久化的用户画像、历史经验、领域知识。相当于黑匣子，记录每次行驶的数据，让系统越跑越聪明。

没有长期记忆的Agent，每次出行都是第一次上路。

### 工具调用 = 传动系统 + 传感器

Tool Calling不是"让LLM调个API"这么简单。它是一个感知-决策-执行的闭环：

1. **感知**：Agent通过工具读取外部状态（数据库查询、网页抓取、传感器数据）
2. **决策**：LLM基于感知结果判断下一步
3. **执行**：调用工具改变外部状态（写数据库、发邮件、执行代码）
4. **反馈**：工具执行结果回传给LLM，进入下一轮循环

这就是**ReAct（Reasoning + Acting）范式**的核心：推理和行动交替进行，每步行动都为下一步推理提供新信息。

LLM本身是个开环系统（输入→输出），Agent通过工具调用把它变成闭环。

### 规划能力 = 导航系统 + 调度中心

规划（Planning）不是简单的"拆步骤"。它解决的是不确定环境下的路径搜索问题：

- **单Agent规划**：ReAct（边想边做）、Plan-and-Execute（先想清楚再做）、Reflection（做完复盘再优化）
- **多Agent协作**：不同Agent各司其职——一个负责规划、一个负责执行、一个负责审查。相当于一个车队，有领航车、工程车、救援车。

规划的本质，是在"行动成本"和"结果质量"之间做权衡。好的Agent不是想得最多，而是在有限步数内达到可用结果。

## 三、不同Agent范式 = 不同的动力系统架构

理解了上面的框架，再看Agent选型就有标准了：

### 对话式Agent（客服/助手）= 城市通勤车

- **架构**：ReAct为主，短平快
- **特点**：工具少、路径固定、强调响应速度
- **核心指标**：首字延迟、意图识别准确率

### 编程Agent（Coder/Devin类）= 工程车

- **架构**：Plan-and-Execute + Reflection，多轮迭代
- **特点**：工具链复杂（编辑器、终端、测试框架），需要自我验证
- **核心指标**：任务完成率、自修复能力

### 交易Agent = 赛车

- **架构**：高频感知 + 低延迟决策 + 严格风控
- **特点**：工具直连市场数据，规划周期极短（秒级甚至毫秒级），容错率极低
- **核心指标**：延迟、夏普比率、最大回撤

### 教育Agent = 家用SUV

- **架构**：长期记忆驱动 + 自适应规划
- **特点**：需要记住学生的学习轨迹、知识盲区、情绪状态，动态调整教学策略
- **核心指标**：留存率、知识点掌握度

**选型不是看模型有多强，而是看架构是否匹配场景。** 用赛车的逻辑做客服，成本高到破产；用通勤车的逻辑做交易，死都不知道怎么死的。

## 四、判断Agent能力的三个硬指标

别被demo骗了。评估一个Agent系统，看这三点：

### 1. 任务完成率（Pass@K）

不是"看起来能做"，而是"实际做成了没有"。给Agent 10个真实任务，能独立完成几个？

### 2. 错误恢复能力

工具调用失败怎么办？LLM幻觉了谁来纠正？好的Agent能在3步内自我修正，差的Agent会一路错到底。

### 3. 成本效率（Cost per Task）

同样一个任务，用GPT-4o花了2块钱，用Claude Sonnet花了5毛，用本地模型花了5分。Agent的商业价值，最终要落到单次任务成本上。

## 写在最后

2023年我们在比发动机马力，2025年我们在比整车工程能力。

LLM的军备竞赛还在继续，但真正的战场已经转移到了系统设计：记忆怎么管？工具怎么调？规划怎么做？多Agent怎么协作？成本怎么控？

**发动机决定了上限，但整车设计决定了你能不能上路。**

你的业务需要造什么车？选什么架构？用什么发动机？想清楚这三个问题，Agent落地就不远了。
